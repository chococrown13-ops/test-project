# Gaffer 26

풋볼 매니저 26(FM26)의 핵심 시스템을 휴대폰 웹에 옮긴 축구 감독 시뮬레이션입니다.
React + TypeScript + Vite(3D는 three.js)로 작성했고, 서버 없이 브라우저에서 전부 동작합니다.
모든 구단·선수·리그는 가상입니다.

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # dist/ 로 정적 빌드
npm run preview  # 빌드 결과물 확인 (http://localhost:4173)
```

휴대폰 세로 화면(390×844) 기준으로 만들었고, PC에서는 가운데 좁은 폭으로 표시됩니다.
`npm run dev`가 출력하는 `Network` 주소로 같은 Wi-Fi의 휴대폰에서 바로 열 수 있습니다.
진행 상황은 브라우저 IndexedDB에 자동 저장됩니다.

## FM26에서 가져온 것

- **공격 시(IP) / 수비 시(OOP) 이중 포메이션** — 공을 가졌을 때와 잃었을 때 다른 포메이션을 씁니다
  (예: 4-3-3으로 막고 3-2-5로 공격). 11명은 두 형태의 자리를 헝가리안 알고리즘으로 짝지어 맡습니다.
- **선수 위치 자유 조정** — 4-4-2·4-2-3-1 같은 기본 틀을 고른 뒤, 경기장 위 선수를 끌어서 23개 지점 어디로든
  옮길 수 있습니다. 왼쪽 풀백만 윙백 자리로 올리는 식의 비대칭 전술이 가능하고, 공격 시·수비 시 화면에서 각각 따로
  조정합니다. 다른 선수 위로 놓으면 두 선수 자리가 바뀌고, '기본 위치로'로 언제든 되돌립니다.
- **역할도 둘로** — 공격 역할 28종(폴스 나인, 채널 포워드, 인사이드 풀백, 하프백…)과 수비 역할 21종
  (커버링 센터백, 프레싱 풀백, 스크리닝 미드필더, 아웃렛 윙어, 트래킹 센터포워드…). 역할마다 핵심 능력치가 있어
  선수별 적합도가 별점으로 보이고, 경기 엔진과 3D 화면의 움직임에 실제로 반영됩니다.
- **비주얼라이저** — 공의 위치(수비·중원·공격 1/3)와 소유 여부에 따라 팀 형태가 어떻게 바뀌는지 보여 줍니다.
- **영입 허브** — 스카우팅 센터, 관심 목록, **영입 요청(Requirements)**: 포지션·역할·나이·예산을 공개하면
  구단과 에이전트가 선수를 제안해 옵니다. **피치 기회(Pitch Opportunities)**: 다른 구단의 요청에 우리 선수를 제안.
- **다이내믹 하이라이트** — 중요한 경기·접전일수록 많은 장면을, 점수 차가 크면 골 위주로 보여 줍니다.
- **외침(Shouts)** — 경기 중 격려·더 요구·집중·칭찬·진정. 10분 쿨다운.
- **홈 타일과 할 일 목록** — FM26 홈 화면처럼 순위·이사회 신뢰·예산·이적시장·사기·최근 경기 타일과,
  답해야 할 제안·만료 계약·불만 선수를 모아 보여 줍니다.

FM26 출시 때 가장 큰 비판이 "클릭이 많고 이전 화면으로 돌아가기 어려운 UI"였기 때문에, 탭 6개 + 뒤로 가기
한 번으로 어디서든 돌아오는 얕은 구조로 만들었습니다.

## 게임 내용

- **세계** — 한 나라, 3부 리그(각 16팀, 30라운드), 48팀이 참가하는 FA컵(1라운드 → 32강 → … → 결승).
  2·3부는 2위까지 자동 승격, 3~6위 승격 플레이오프, 1·2부 하위 3팀 강등.
- **선수** — FM과 같은 1~20 능력치 47종(기술·멘탈·피지컬·골키핑), 숨은 성격 10종, 현재/잠재 능력(CA/PA),
  포지션 숙련도, 주발·키. 스카우팅 정보가 부족하면 능력치가 범위나 '?'로 보입니다.
- **경기 엔진** — 1분 단위. 빌드업(압박 상대) → 전진(스크린 상대) → 찬스 생성(최종 수비 상대) 단계를 역할별 가중
  능력치로 판정하고, 찬스는 종류(스루패스·크로스·컷백·드리블·중거리·역습·롱볼·코너·프리킥·PK)와 xG를 가집니다.
  체력 소모, 경고·퇴장(경고 누적 정지 포함), 부상, 평점, 연장전·승부차기.
- **3D 경기 화면** — 찬스 종류에 맞춰 크로스·컷백·스루패스·중거리·PK·프리킥 벽·코너킥 장면을 연출하고,
  골이면 슬로모션 리플레이(사이드·골대 뒤·반대편 세 가지 앵글). 공 소유에 따라 IP/OOP 형태로 움직입니다.
  2층 관중석과 지붕, 한 번의 드로우콜로 그리는 수천 명의 관중(골이 나면 점프), 스크롤되는 LED 광고판,
  조명 블룸, 공이 들어가면 출렁이는 골망, 슈팅 궤적, 등에 풀네임과 등번호가 박힌 유니폼.
  선수는 모션 캡처 애니메이션이 들어간 사람 모델이고, 사진으로 찍은 밤하늘과 잔디 질감을 씁니다(아래 '3D 에셋과 라이선스').
  저사양 폰은 자동으로 화질을 낮추고(그림자·블룸 끄고 관중 줄임) 2D로도 볼 수 있습니다.
- **선수 얼굴과 엠블럼** — 메뉴의 선수 얼굴은 3D 모델과 같은 피부·머리 모양으로 그려지고, 구단 엠블럼은
  구단 색과 줄무늬·반반·사선 같은 패턴의 방패로 만들어집니다. 선수 이름은 어디서나 풀네임으로 표시합니다.
- **경기일** — 기자회견, 경기 전·하프타임·경기 후 팀 토크(선수별 반응), 교체 5회, 경기 중 전술·포메이션 변경, 외침,
  코치에게 교체 맡기기.
- **이적** — 구단별 요구 이적료, 입찰·역제안, 선수 계약 협상(주급·기간·팀 내 위상), 임대(주급 분담), 자유계약,
  재계약, 바이아웃, 방출 위약금. 여름(7~8월)·겨울(1월) 이적시장. AI 구단끼리도 사고팔고 우리 선수에게 제안합니다.
- **훈련·성장** — 팀 훈련 초점 8종과 강도, 개인 훈련. 나이·잠재력·성격·코치·시설·출전 시간으로 성장하고,
  30대부터 피지컬부터 떨어집니다. 매년 3월 유스 인테이크.
- **구단 운영** — 주급·관중 수입·중계권·스폰서·상금, 이적/주급 예산 조정, 스태프 고용·해고(코치·스카우트·의무·유스),
  이사회 목표와 신뢰도, 경질과 새 구단 제의.

## 3D 에셋과 라이선스

- **선수 모델과 동작** — Mixamo(Adobe)의 X Bot 캐릭터와 대기·걷기·달리기 모션 캡처(three.js 예제에 포함된
  `Xbot.glb`). Mixamo 캐릭터와 애니메이션은 게임 등 프로젝트에 로열티 없이 쓸 수 있습니다(원본 파일 단독 재배포는 불가).
  `scripts/build-player-model.mjs`가 메시 두 개를 합치고 정점을 2만 8천 개에서 약 4천 개로 줄인 뒤, 손가락 동작을 빼고
  meshopt로 압축해 `public/models/player.glb`(약 380KB)를 만듭니다. 유니폼 색은 정점마다 기록한 신체 부위와
  기본 자세의 높이로 셰이더가 칠하고, 얼굴·머리카락·등번호·이름은 게임이 뼈에 붙입니다.
  차기·터치·다이빙·세리머니는 모션 캡처 위에 뼈 회전을 더해 만듭니다. 모델을 못 불러오면 예전의 단순한 선수로 그립니다.

  ```bash
  curl -O https://raw.githubusercontent.com/mrdoob/three.js/r180/examples/models/gltf/Xbot.glb
  node scripts/build-player-model.mjs Xbot.glb
  ```
- **밤하늘** — Poly Haven의 Kloppenheim 02 (Pure Sky), CC0. 2048×1024 JPG로 줄여 `public/models/night-sky.jpg`.
- **잔디 표면** — Poly Haven의 Leafy Grass 노멀 맵, CC0. 512px로 줄여 `public/models/grass-normal.jpg`.

## 밸런스

1부 720경기를 시뮬레이션해 맞춘 값입니다.

| 지표 | 결과 | 실제 리그 참고값 |
| --- | --- | --- |
| 경기당 득점 / xG | 2.71 / 2.83 | ~2.7 |
| 홈승 / 무 / 원정승 | 46% / 22% / 33% | ~44% / 25% / 31% |
| 경기당 슈팅 (유효) | 24.9 (10.7) | ~25 (~9) |
| 경기당 경고 / 퇴장 | 2.96 / 0.16 | ~3.5 / ~0.15 |
| 경기당 오프사이드 / 부상 | 3.3 / 0.29 | ~3.5 / - |

같은 선수단으로 전술 프리셋을 바꿔 240경기씩 돌리면 경기당 승점이 1.25~1.63으로 갈리고, 게겐프레싱은 득점이,
낮은 블록은 실점 억제가 두드러집니다. 3시즌 연속 시뮬레이션으로 선수 중복·소속 불일치가 없는지, 승강이 3팀씩
맞는지 확인했습니다.

## 배포

`main`에 푸시되면 `.github/workflows/deploy.yml`이 빌드해 GitHub Pages로 배포합니다.
Actions 탭에서 수동 실행(`workflow_dispatch`)도 가능해 머지 전에 미리 확인할 수 있습니다.

최초 1회만 저장소 설정이 필요합니다: **Settings → Pages → Source 를 "GitHub Actions"로 변경.**

백엔드가 없는 정적 사이트라 Netlify, Vercel, S3 등 어디에 올려도 그대로 동작합니다.
`vite.config.ts`의 `base: './'` 덕분에 하위 경로(`/test-project/`)로 서빙해도 문제가 없습니다.

## 과일 톡톡 (`games/merge/`)

같은 저장소에 들어 있는 두 번째 게임으로, 수박게임 스타일의 물리 합치기 퍼즐입니다.
같은 과일끼리 닿으면 한 단계 큰 과일이 되고, 과일이 점선 위로 2.5초 넘게 쌓여 있으면 게임이 끝납니다.

```bash
npm run dev:merge   # http://localhost:5173/games/merge/
```

- **조작** — 휴대폰은 드래그로 위치를 정하고 손을 떼면 떨어집니다. PC는 마우스를 움직이고 클릭,
  또는 ←/→ 이동 후 스페이스.
- **과일 11단계** — 체리 › 딸기 › 포도 › 귤 › 감 › 사과 › 배 › 복숭아 › 파인애플 › 멜론 › 수박.
  떨어뜨릴 수 있는 건 앞의 5개뿐이고 나머지는 합쳐서 만들어야 합니다. 수박 두 개가 합쳐지면
  보너스 100점과 함께 사라집니다.
- **점수** — 만들어진 과일 단계에 따라 1, 3, 6, 10…점. 0.9초 안에 연달아 합치면 콤보 보너스.
- **연출** — 과일 그림은 전부 캔버스로 그려 단계별로 한 번만 스프라이트로 굽습니다(이미지 파일 없음).
  합쳐질 때 파티클·점수 팝업·진동, 큰 과일은 화면 흔들림. 효과음은 Web Audio로 합성합니다.
- **기록** — 최고 점수와 지금까지 만든 가장 큰 과일이 `localStorage`에 남고, 하단 진화표에서
  아직 못 만든 과일은 회색으로 표시됩니다.

물리는 [matter-js](https://brm.io/matter-js/)를 쓰고, 게임 규칙(`game.ts`)은 DOM을 전혀 참조하지 않습니다.
빌드하면 `dist/games/merge/`로 함께 나오므로 GitHub Pages에서는 `…/test-project/games/merge/`로 열립니다.

```
games/merge/
  index.html       페이지와 HUD·오버레이 마크업
  src/fruits.ts    과일 단계 정의와 캔버스 그림
  src/game.ts      matter.js 월드, 합치기·콤보·게임오버 규칙
  src/audio.ts     Web Audio 효과음
  src/main.ts      렌더링, 입력, HUD
```

## 스도쿠 도장 (`games/sudoku/`)

중·상·최상·극상 네 난이도의 스테이지와, 풀이 기법을 배우는 학습 채널이 있는 스도쿠입니다.

```bash
npm run dev:sudoku   # http://localhost:5173/games/sudoku/
```

- **스테이지** — 난이도마다 50개, 번호가 클수록 어렵습니다. 클리어 기록(시간·실수·힌트)과
  진행 중인 판이 저장되고, 홈에서 이어하기로 바로 돌아갑니다.
- **난이도 판정** — 사람처럼 푸는 풀이기(`solver.ts`)가 가장 쉬운 기법부터 적용해 끝까지 풀었을 때
  필요했던 가장 어려운 기법으로 정합니다. 모든 스테이지는 학습 채널에서 가르치는 기법만으로 풀리고,
  답이 하나뿐입니다.

  | 난이도 | 반드시 한 번 이상 필요한 기법 |
  | --- | --- |
  | 중 | 포인팅, 클레이밍, 네이키드/히든 페어 |
  | 상 | 네이키드/히든 트리플, X-윙, XY-윙 |
  | 최상 | 스카이스크래퍼, 투스트링 카이트, 터봇 피시, 소드피시, XYZ-윙, W-윙, 유니크 렉탱글, 쿼드 |
  | 극상 | 젤리피시, X-체인, XY-체인 |

- **학습 채널** — 23가지 기법을 5개 장으로 나눠 설명, 찾는 법, 실제 퍼즐에서 뽑은 예시 보드를 보여 줍니다.
  기법마다 연습 문제 5개가 있고, 지울 수 있는 후보를 직접 탭해서 맞힙니다(같은 기법의 다른 정답도 인정).
- **힌트** — 지금 판면에서 다음에 쓸 기법의 이름과 이유를 보여 주고, 패턴 칸·후보·체인 연결선을
  보드에 표시합니다. `배우기`를 누르면 그 기법의 학습 페이지로 갑니다. 틀린 숫자가 있으면 그것부터 알려 줍니다.
- **조작** — 메모, 자동 메모, 되돌리기, 지우기. PC에서는 숫자키·방향키·`N`(메모)·Ctrl+Z.
- **테마 두 가지** — 홈 화면이나 게임 메뉴에서 고릅니다(처음엔 기기의 다크 모드 설정을 따름).
  - **먹** — 먹빛 바탕, 상아색 명조 숫자(Cormorant Garamond · 나눔명조), 금색 가는 선, 붉은 네모 인장 「解」.
  - **봄** — 점무늬 크림색 종이, 굵은 갈색 테두리와 스티커 그림자, 둥근 숫자(Fredoka · 주아),
    분홍 「참 잘했어요」 도장.
- **도장판과 손맛** — 스테이지 목록은 도장판이라, 한 판을 풀 때마다 도장이 찍힙니다. 클리어하면 보드에
  물결이 지나간 뒤 도장이 내려찍히고, 행·열·박스를 완성할 때도 그 줄에 물결이 지나갑니다.
  바둑돌 놓는 듯한 효과음과 진동(지원 기기)은 메뉴에서 끌 수 있습니다. 아이콘은 모두 직접 그린 선 아이콘입니다.
- 웹폰트는 Google Fonts에서 불러오되 로딩을 막지 않아서, 폰트가 늦거나 막혀도 게임은 바로 시작됩니다.

### 퍼즐 다시 만들기

스테이지와 연습 문제는 미리 생성해 `src/data/`에 JSON으로 들어 있습니다(브라우저에서 생성하지 않음).

```bash
cd games/sudoku
for i in 1 2 3 4; do node --experimental-strip-types scripts/generate.ts $((i*7919)) 700 /tmp/run$i.json & done; wait
node --experimental-strip-types scripts/merge.ts /tmp/run*.json
```
